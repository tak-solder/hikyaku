# write: retrospective.md の書き込みと提示

- [ ] retrospective.md を以下のテンプレートに従って作成する。出力先は directive の `値` の `output`
  （既にあれば追記モード）

新規作成の場合:

```markdown
# {フェーズヘッダー}

## 予測ピークの振り返り

（`build-{NN}` のときだけ置く。他のフェーズでは節ごと省く）

| 段階 | 予測ピーク | 根拠 |
|------|------------|------|
| architectフェーズ段階 | 〇k | issue.md の内訳 |
| builderフェーズ段階 | 〇k | plan.md の内訳（下表） |

**セッション**: （1セッションで完結 / 途中で分割（build-NN を追加）/ 〇セッション）

**乖離**: （セッションの実測のピーク − builderフェーズ段階。±10% 以内なら「なし」と書いてよい）

**乖離の要因**: （乖離があった場合のみ。成分ごとに、どちらへ、なぜ読み違えたかを書く。
　例:「読み込みを 110k と見たが、共通の型の変更が波及して呼び出し元を 20 ファイル読んだ（+90k）」。
　成分の見積もりは合っていたのに外れたなら、ガイドの見積もり方（換算の目安・固定費）の問題として書く。
　乖離が無ければ「なし」）

### builderフェーズ段階の内訳

（plan.md の内訳表をそのまま転記する。最後の行のガイドの版も消さない）

| 成分 | 予測 | 根拠 |
|------|------|------|
| ... | ... | ... |

### セッションの実測

（`tokens session --markdown` の出力をそのまま貼る）

| 計測項目 | 値 |
|------|------|
| ピーク | ... |
| 開始時の固定分 | ... |
| 呼び出し回数 | ... |
| 出力トークン | ... |
| コンパクション | ... |
| ウィンドウ | ... |
| モデル | ... |
| ホスト | ... |
| Hikyaku | ... |
| セッション | ... |

### 差分の集計

（`tokens history build-{NN} --markdown` の出力をそのまま貼る）

| 差分の集計 | 値 |
|------|------|
| 新規ファイル数 | ... |
| 変更ファイル数 | ... |
| 追加行数 | ... |
| 削除行数 | ... |
| 生成物（数えていない） | ... |

## セッション中にスキル外で受けた指示

（スキルの手順に含まれていないが、ユーザーから受けた指示・修正・補足を列挙する。
　スキル外の指示がなかった場合は「なし」）

## 永続化すること

（以後に効く知見。1件1行で、宛先・重要度・そのまま書ける文面・根拠を書く。無ければ「なし」）

- `conventions` [中]: （文面）（根拠: どの指示・どの出来事か）
- `workflow` [中]: （文面）（根拠）

## 役に立たなかった記述

（読み込まれた・読んだ記述のうち、役に立たなかったもの。無ければ「なし」）

- `AGENTS.md`「（見出しか冒頭の数語）」: 古い（何と食い違うか）
- `rule:.claude/rules/{名前}.md`「…」: 無関係（今回触った範囲）
```

**節の見出しと行の形を変えない。** `hikyaku promotions` が見出しと行頭を読み、close-cycle が
サイクル全体の分を束ねる。書式は `${CLAUDE_PLUGIN_ROOT}/skills/close-cycle/references/persistence.md` の
「記録の書式」。重要度が低の知見は書かない。

「予測ピークの振り返り」は記録であって、永続化の候補ではない。乖離そのものを「永続化すること」に
起こさない（見積もりの見直しは、close-cycle が乖離を見て `/hikyaku:token-guide` を呼ぶ）。
ただし、乖離の要因がこのリポジトリ固有の設計上の条件に落ちる場合は、通常どおり宛先を選んで書く。
Hikyaku の見積もり手順そのものへの提案は `workflow` に書く。

フェーズヘッダーは呼び出し元のフェーズで決める。

| フェーズ | ヘッダー |
|---|---|
| `plan`（`planning`） | `企画フェーズ 振り返り` |
| `architect`（`design`） | `設計フェーズ 振り返り` |
| `build-{NN}` | `Build {NN}: {ビルド名} 振り返り`（issue.md からビルド名を取得） |

追記モードの場合（PRレビュー対応）: 既存の末尾に以下のセクションを追加する。同じ見出しを下位のレベルで
繰り返してよい（`hikyaku promotions` は見出しのレベルを問わず拾う）。

`build-{NN}` で「予測ピークの振り返り」が既にある場合は、節を増やさず既存の表を上書きする。
PR レビュー対応で作業が増えれば実測も変わるので、peak-actual で測り直した値（セッションの実測・
差分の集計）に差し替え、乖離と要因を書き直す（予測側の行と内訳は変えない）。

**この節の形（段階表 / セッション行 / 内訳表 / セッションの実測表 / 差分の集計表）は変えない。**
`hikyaku tokens history` が見出し名で読み、`/hikyaku:token-guide` がガイドを補正する素材にする。

```markdown

（なければ「なし」。形式は新規作成時と同じ）
```
