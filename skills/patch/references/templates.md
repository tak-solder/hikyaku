# patch のテンプレート

## PR の本文

依頼・合意・検証の正はこの本文。pr で作り、publish で検証とドキュメントを埋める。
コード・diff から分かること（変更したファイルの一覧、実装の詳細）は書かない。

```markdown
## 依頼

（受け取った依頼。QA のフィードバックなら項目ごとに原文を引用する）

## 合意した挙動

### P-1: {項目名}

- 現状: （再現条件・該当箇所）
- 期待する挙動: （変更後にどうなるか）
- 対応範囲: （変えるもの / 変えないもの）
- 検証方法: （テスト / 手元での確認）
- マージ時点のデータ安全: （根拠。触れなければ「該当なし」）

### P-2: …

## 関連

- サイクル: {cycle}（統合ブランチ {startPoint} 宛て / マージ後・CLOSE 前）　※サイクルに属さなければ「なし」
- 通常のサイクルへ引き継いだ項目: （引き継いだサイクル。無ければ「なし」）

## 検証

（publish で書く。実行したコマンドと結果、手元で確かめた内容）

## ドキュメント

（publish で書く。直した永続ドキュメント、またはサイクルの handoff.md へのリンク。無ければ「なし」）

## 残したこと

（publish で書く。そのまま進めたレビュー指摘、「確度: 要確認」の懸念、hook / upstream の候補。無ければ「なし」）
```

## handoff.md（サイクルに属す patch だけ）

`{unitDirectory}/handoff.md` に置く。そのサイクルの close-cycle が `hikyaku promotions` で読む。
永続化するものが無ければ作らない（persist を skipped にする）。

```markdown
# patch {phase}: {依頼の要約} 申し送り

## 永続化すること

- `overview` [中]: （そのまま書ける文面）（根拠。design-delta の予定から変えたならその旨）
- `rule:.claude/rules/{名前}.md` [中] 済: （この PR で書いた rule の一行の要約）
```

行の形・宛先・重要度は `${CLAUDE_PLUGIN_ROOT}/skills/close-cycle/references/persistence.md` の「記録の書式」に従う。

## intake.md（通常のサイクルへの引き継ぎ）

create-cycle が新しいサイクルの `planning/intake.md` に書く。planner がチケットと同じく企画の入力にする。
patch のブランチは PR にしないので、ここに書かなかった調査結果は失われる。

```markdown
# patch からの引き継ぎ: {依頼の要約}

## 依頼

（受け取った依頼。項目ごとに原文を引用する）

## 調べたこと

（項目ごとの現状・再現条件・該当箇所。コードへのパスで指す）

## 合意したこと

（期待する挙動のうち、ユーザーと合意できたもの。未合意なら「なし」）

## サイクルに回した理由

（fit で当たった観点と根拠）

## 未決事項

（企画で決めること）
```
