# P1: 対応方針の合意

依頼について、何をどう変えるかの合意を取る。合意は人間の判断なので、どのプロファイルでも省かない。

- [ ] 項目ごとに、scope で作った案を提示する

```
P-1: 一覧の並び順
  現状:       作成日の昇順（OrderList::query の ORDER BY）
  期待する挙動: 更新日の降順。同じ更新日なら ID の降順
  対応範囲:   一覧画面と CSV 出力。API の既定の並び順は変えない
  検証:       並び順のテストを追加する
  データ安全: 該当なし

P-2: …

PR の向き先: {startPoint}（{サイクルに属す / 属さない}）
```

  - 合意済みの要件や設計（サイクルに属す patch の user-stories.md・design-delta.md）と食い違う項目は、
    食い違いを明示する
  - fit で「それでも patch で進める」と決めた項目は、当たった観点と進める理由を添える
- [ ] 承認されたら `approved` を報告する。`--input` には合意した範囲が分かるように書く
- [ ] フィードバックがあれば `rejected` を報告し、案を直して提示し直す
