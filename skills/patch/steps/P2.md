# P2: 永続ドキュメントの更新の承認

サイクルに属さない patch は、永続ドキュメントをこの PR で直す。何を足し・置き換え・消すかの
取捨選択は人間の判断なので、どのプロファイルでも省かない。

- [ ] 置き場を確かめる
  - 論理名は `document-guide.md` が正。「対象外」の論理名へは書かない。「未作成」なら新規作成になるので、
    その旨を併せて承認を得る
  - `overview` にテーブル一覧・エンドポイント一覧・依存パッケージの版を書かない。正の所在へのポインタを書く
  - `conventions` に、一部のファイルにしか効かない注意を入れない（それは rule）
  - 置き換えと削除を提案できるのは、この変更で事実でなくなった記述だけ。それ以外で気づいた点は、
    手を入れずに PR の本文に書く
  - ADR の本文は書き換えない。この変更で判断を覆すなら、旧エントリを `superseded` にして新しく起こす
- [ ] 置き場ごとに、追加（`+`）・置き換え（`~`）・削除（`-`）を分けて示す。根拠を添える

```
overview:
  ~ 「一覧」: 「作成日の昇順で表示する」→「更新日の降順で表示する」（P-1 で変更）

conventions（AGENTS.md）:
  + [中] 一覧の並び順は OrderList::query だけで決める（P-1 で、画面ごとに並べ替えていた箇所を1つにした）

PR の本文に載せるだけ:
  - hook: …
```

- [ ] 承認されたら `approved` を報告する。`--input` には承認した範囲が分かるように書く
- [ ] フィードバックがあれば `rejected` を報告し、候補を直して提示し直す
