# collect: 予測と実測の収集

- [ ] 予測と実測を集める

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/hikyaku.mts" tokens history
node "${CLAUDE_PLUGIN_ROOT}/scripts/hikyaku.mts" tokens history --group-by guide
```

各ビルドについて architect / builder 段階の予測ピーク、実測のピーク、乖離（実測 − builder 段階）と比率、
開始時の固定分、区切りでのコンテキスト（G8・実装前・レビュー前）、呼び出し回数・コンパクション、
差分の追加行数、モデル・ガイドの版・Hikyaku の版・ホスト、セッションが完結したかが並ぶ。
読めない項目は「—」で出る。推測で埋めない。

モデル・ホスト・ガイドの版が混ざっているときは `--group-by model`（`host` / `guide` / `hikyaku`）で分けて読む。
予測の当たり方はモデルの世代やガイドの版で変わるので、混ぜたまま判断しない。

- [ ] 乖離のあるビルドの `retrospective.md` を読み、「乖離の要因」を確認する
  - どの成分をどちらへ読み違えたかが書かれている。書かれていなければ、区切りでの値（どこで膨らんだか）と
    差分の集計（書いた量）から判断する
- [ ] 今のガイドを読む（`tokens guide` が示すパス）

## 成分の読み違えか、見積もり方の問題か

乖離には2種類あり、直す場所が違う。

| 乖離の種類 | 見え方 | 直す場所 |
|---|---|---|
| 成分の読み違え | 読むファイル・書く量を数え損ねていた。未知の領域を 0 にしていた | ガイドの成分の節に、数え漏れやすいものを足す |
| 見積もり方の偏り | 成分の列挙は合っていたのに、同じ向きに外れ続ける（比率の平均が 1 から離れている） | ガイドの換算の目安・固定費の値 |

1件だけのぶれでは直さない。直した前と後の予測は `--group-by guide` で分かれるので、次の校正で効果を確かめられる。
