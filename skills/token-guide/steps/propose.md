# propose: ガイドの変更案の作成

素材が無い（予測と実測を並べた振り返りがまだ無い）場合は、ユーザーが変更内容を指定している場合だけ
変更案を作る。実測無しに見積もり方を動かすのは推測なので、こちらから提案はしない。
作らないなら `skipped` を報告する。承認と書き込みは行わず、PR へ進む。

- [ ] 素材から変更案を作り、根拠を添えてユーザーと決める
  - close-cycle から呼ばれた回（`auto`）では、ユーザーと決めずに変更案を作り、承認を挟まずに書き込みへ進む
    （`step next` が `approve` を返さない）。採否は PR のマージで決まるので、根拠を PR の本文で
    判断できるように控えておく。偏りがはっきりしない（1件だけのぶれ、原因が分からない外れ）なら、
    変更案を作らず `skipped` を報告する

| 変更 | 書く場所 | 例 |
|---|---|---|
| 数え漏れやすいものの追加 | 該当する成分の節 | 読み込み: 「`packages/shared/` の型に触れたら、利用側のパッケージの index も読む」 |
| 換算の目安・固定費の補正 | 該当する成分の節 | 固定費: 「実測の固定分の中央値 52k + 手順の進行分 40k」 |
| このリポジトリで重い作業 | 「このリポジトリでの補正」 | 「docker compose の環境に触れるビルドは未知の領域に 100k を見込む」 |

- 根拠のビルドと数値（乖離・比率・件数）を、補正の文と一緒に書く。次の校正で、その補正がまだ効いているかを判断できるように
- 既存の補正を黙って書き換えない。外すなら、なぜ不要になったか（モデルが変わった、作業の性質が変わった）をユーザーに確認する
- 標準のガイドの前提や成分の定義を変える提案は、このリポジトリのガイドではなく Hikyaku への提案（issue）にする
