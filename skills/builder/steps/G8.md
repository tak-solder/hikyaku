# G8: plan と test-spec の承認

plan.md と test-spec.md をまとめてユーザーに提示し、承認を得る（G8）。
この承認は profile の管轄外で、どのプロファイルでも省略しない。

- [ ] コンテキストを確かめる（directive の `context`）
  - 目安を超えていたら、提示の前に、残りの作業（実装・検証・レビュー・PR・振り返り）を見て
    継続するか分割するかを自分で判断する。コードを書く前の今が、最も安く分割できる
  - 分割するなら、`/hikyaku:build-manager {cycle}` を呼び、plan.md を見直してから提示する
  - 継続するなら、**提示の中で、目安を超えていることと継続する理由を伝える**
  - 計測不可なら、その旨を1行添えて見積もりだけで進める
- [ ] plan.md と test-spec.md をまとめて提示し、承認を求める
  - 承認観点: 実装ステップの妥当性 / 受け入れ基準の網羅性 / 正常系・異常系・境界値のカバー範囲 / 不要なテストの有無
  - thorough では G7 で plan を既に承認しているので、test-spec に焦点を当てる
- [ ] 承認されたら `approved` を報告する（`--input` にユーザーの答え）。承認は plan.md と
  test-spec.md のハッシュに結びつくので、承認後に直すと取り直しになる
- [ ] フィードバックがあれば `rejected` を報告し（`--input` にユーザーの答え）、反映してから
  `step next` に従って提示し直す。提示し直すたびにコンテキストは測り直される
- [ ] コミット & push する（progress.jsonl も含める）
