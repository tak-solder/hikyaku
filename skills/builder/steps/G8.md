# G8: plan と test-spec の承認

plan.md と test-spec.md について、ユーザーが判断すべきものだけを提示し、承認を得る（G8）。

- [ ] コンテキストを確かめる（directive の `context`。完了時点の見込みと推奨はスクリプトが出す）
  - 推奨が「継続」なら、そのまま提示に進む
  - 推奨が「分割」なら、`/hikyaku:build-manager {cycle}` を呼び、plan.md を見直してから提示する
  - 推奨が「切り替え」なら、提示の中で、G8 の承認のあとにこのセッションを終えて、新しいセッションで
    implement から続けることを伝える（切り替えは implement の手前で記録する）
  - 推奨と違う手を選ぶなら、スクリプトに見えない事情（後ろに回せる実装ステップが無い、読み直しを plan.md の
    ポインタに絞れる、など）を、**提示の中で、見込みの値と一緒に伝える**
  - 計測不可なら、その旨を1行添えて見積もりだけで進める
- [ ] 提示の中身をスクリプトに組み立てさせる

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/hikyaku.mts" gate brief G8 build-{NN} {cycle}
```

- [ ] 出力（「（解釈）」の印が付いたシナリオと、どのシナリオにも対応していない受け入れ基準）に、plan.md の
  要点（実装ステップと、issue.md に無い追加があればそれ）を添えて提示し、承認を求める
  - 番号で追跡できないと出たら、出力された受け入れ基準の節と plan.md の実装ステップで網羅性を示す
  - test-spec をスキップしたと出たら、plan.md を提示する
  - 全文は、ユーザーが求めたときに `--full` を付けて出す
  - 承認観点: 解釈で決めた振る舞いの妥当性 / 未対応の受け入れ基準の扱い / 実装ステップの妥当性
  - G7 で plan を既に承認しているなら、test-spec に焦点を当てる
- [ ] 差し戻されたら、提示し直すたびにコンテキストは測り直される
