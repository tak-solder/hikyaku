# 予測ピークの見積もりガイド（標準）

ビルドを1つのセッションで実装から PR まで進めたとき、メインセッションのコンテキストが
どこまで膨らむか（予測ピーク）を、成分ごとに見積もるためのガイド。

`{HIKYAKU_ROOT}/token-guide/guide.md` があれば、このガイドの代わりにそちらを使う
（`hikyaku tokens guide` が有効なほうを示す）。プロジェクトのガイドは、このガイドをコピーして
このリポジトリの実績で補正したもの。

## 前提

- 測るのはメインセッションだけ。サブエージェント（doc-reviewer・テスト仕様の生成など）に委任した作業は、
  委任の指示と返ってきた結果の分しか増えない
- コンテキストは減らない。一度読んだファイル・ツールの出力・自分が書いたコードは、セッションの最後まで残る。
  だから成分は足し算で効き、最大値では効かない
- 同じファイルを何度も読めば、そのたびに増える。編集のたびに差分の前後が載る
- ここに書いた換算の目安は校正前の出発点。`hikyaku tokens history` の実測と比べて外れが続くなら、
  プロジェクトのガイドで補正する

## 成分ごとの見積もり方

成分は5つ。どれも「該当しない」と判断したら 0 を渡す。考えなかった成分を省かない。

### 固定費（`--fixed`）

セッションの開始時に載る分（システムプロンプト・スキル本文・リポジトリのルール）と、手順を進めるたびに
載る分（step の指示ファイル・報告の出力・ゲートの提示）。

- `hikyaku tokens history` に実測があれば、「固定分」（開始時のコンテキスト）の中央値に、
  手順の進行分として 30k〜50k を足す
- 実測が無ければ 80k〜100k を出発点にする
- リポジトリのルールファイルがパス指定で読み込まれる（`.claude/rules/` など）なら、触れるパスに
  当たるルールの大きさを足す。読み込みではなくここに入れる（ビルドの中身と関係なくかかるため）

### 読み込み（`--reading`）

読むドキュメントとコード。plan.md を書くまでの調査が大半を占め、最も外れやすい成分の1つ。

- 読むファイルを名前で列挙し、大きさを見積もる。列挙は成果物（issue.md / plan.md）に残す
  （レビューで検証できるようにするため）
- 換算の目安: コードはおよそ 4 文字で 1 トークン、日本語の文章はおよそ 1〜1.5 文字で 1 トークン
- 永続ドキュメント・設計ドキュメント（design-delta.md など）・issue.md・plan.md・test-spec.md を含める。
  サイクルを重ねると永続ドキュメントは大きくなるので、前のビルドの値を流用しない
- 変更するファイルは、変更する前に読む。参照元・呼び出し元・共有する型まで辿るなら、それも数える
- grep や一覧の出力も載る。探索の範囲が広いほど増える

### 実装（`--implementation`）

テストを除くコードの生成と編集。

- 新規ファイルは書いた量がそのまま載る。既存ファイルの編集は、編集の前後の差分と、
  確認のための読み直しが載る
- 目安: 書く行数 × 10〜15 トークンを基本に、編集の繰り返しと読み直しで 2〜3 倍を見込む
- 作成するファイルを名前で列挙し、ファイルごとに行数を概算してから合計する

### テスト（`--tests`）

テストコードの生成と、テストの実行結果の読み込み。

- テストコードは実装と同じ数え方をする。シナリオの数（test-spec.md の見出し、または受け入れ基準の数）と、
  種別（unit / integration / e2e）で重さが変わる。e2e は準備と出力が大きい
- テストを実行するたびに出力が載る。失敗の出力（スタックトレース）は長い

### 未知の領域（`--unknown`）

見通せない作業。最も大きく振れる成分で、外れの大部分はここから来る。

- 環境構築やデバッグ（コンテナ・ビルドツールの設定、依存の解決）
- 外部ライブラリの内部の調査（vendor 配下や依存のソースを読む）
- ローカル検証で失敗が続いたときの修正のループ（型エラー・lint・テストの失敗の繰り返し）
- 初めて触る領域、設計ドキュメントに書かれていない既存の挙動への依存

該当しそうなら、読み込みと実装に上乗せせず、ここで別に見積もる。見積もりの根拠
（何が見通せないか）を `--unknown-basis` に書く。

## 過小見積もりになりやすいもの

- 読み込みで、変更するファイル以外（呼び出し元・共有する型・テストの補助）を数え忘れる
- 検証と修正のループを見込まず、未知の領域を 0 にする
- 編集を繰り返す大きなファイル。編集のたびに前後が載る
- PR レビュー対応や差し戻しで、同じセッションの中でもう一度読み直す

## このリポジトリでの補正

（標準のガイドでは空。プロジェクトのガイドに、close-cycle の昇格や `/hikyaku:token-guide` が
実績から得た補正を書き足す。例:「このリポジトリでは型定義の変更が全パッケージのテストに波及するので、
共通の型に触れるビルドはテストに 50k を足す」）
