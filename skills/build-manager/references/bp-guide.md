# ビルドポイント（BP）見積もりガイド

## BP定義

AIエージェントとの1セッション（20万トークン）で実装が完了することを基準とした定量指標。

| BP | 判定 |
|----|------|
| `bp_max − 3` 以下（既定 5 以下） | 1セッションで完結見込み |
| `bp_max − 2` 〜 `bp_max`（既定 6〜8） | 分割推奨（分割コストが大きい場合のみ許容） |
| `bp_max + 1` 以上（既定 9 以上） | 分割必須 |

`bp_max` は `.hikyaku.config` の値（`hikyaku config {cycle} --json` の `bpMax`）。

## 基準表はワークスペースの持ち物

しきい値と加算要素の表は **このファイルには無い**。正は `{HIKYAKU_ROOT}/bp-guide/rules.toml` で、
無ければ Hikyaku の既定値が使われる。現在有効な表は次で確認する。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/hikyaku.mts" bp guide {cycle}
```

人間向けの説明と、そのリポジトリ固有の数え方の注意は `{HIKYAKU_ROOT}/bp-guide/README.md` にある
（存在する場合）。**見積もりの前に読む。** 「マイグレーション1本は新規ファイル2つと数える」のような
注意はここにしか無い。

## 分担

| 誰が | 何を |
|---|---|
| あなた（LLM） | 入力値を見積もる（新規ファイル数はいくつか、影響ファイル数はいくつか、決済 API を叩くか） |
| `hikyaku bp estimate` | 入力値を基準表に当てて BP にする |

**表を読んで自分で BP にしない。** 当てはめをコマンドに寄せているのは、見積もりが外れたときに
「入力値を読み違えた」のか「基準表がこのリポジトリに合っていない」のかを切り分けるため。
自分で当てはめると、その切り分けができなくなる。

## 見積もり手順

1. ビルドが触るワークスペース（パッケージ）を特定する
2. ワークスペースごとに入力値を見積もり、`bp estimate` を実行する

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/hikyaku.mts" bp estimate {cycle} \
  --new-files 5 --lines 800 --impact-files 7 --setup --markdown
```

3. 全ワークスペースの BP を合計する（`--workspace <name>` で出力に名前を添えられる）
4. `--markdown` の内訳表を成果物（issue.md / plan.md）に貼る。**転記せず、出力をそのまま貼る**

単一ワークスペースの場合は 1・3 を省略してよい。

使える入力（`--<キー>`）は基準表で決まる。`bp guide` の「入力」列がそのまま渡し方。
**基準表に無いフラグはエラーになる。** タイプミスで加算要素が黙って落ちると、そのまま過小見積もりになるため。

## 入力値の数え方

過小見積もりの多くは、表の読み違えではなく入力値の数え漏れから来る。

- **新規ファイル数**: 作成するファイルを**名前で列挙してから**数える。テスト・型定義・
  マイグレーション・設定ファイルも含める。列挙は成果物に残す（レビューで検証できる）
- **実装行数**: 列挙したファイルごとに概算し、合計する。テストを含める
- **API操作数 / 画面数 / DBテーブル数**: 設計ドキュメント（design-delta.md）から数える
- **影響ファイル数**: 変更するファイルではなく、**変更の影響を理解するために読むファイル**。
  codebase-survey.md と設計ドキュメントから、参照元・呼び出し元・共有する型まで辿る
- **加算要素**: 該当するものをすべて付ける。迷ったら付けて、レビューで外す
- **指定しなかった指標は「未指定」として出力に残る。** 該当しない（0）なら 0 を渡す。
  未指定と 0 は違う（未指定は「考えなかった」、0 は「考えて無いと判断した」）

## 分割戦略（合計BP が `bp_max` 超の場合）

1. 主要な分割軸を特定する
   - ワークスペースが分離可能 → ワークスペース単位で分割
   - 「基盤セットアップ」と「機能実装」が混在 → 分離
   - 独立した画面が3つ以上 → 画面単位で分割
   - 独立したドメインが3つ以上 → ドメイン単位で分割
   - 外部連携が2つ以上 → 連携先ごとに分割
2. 分割後の各ビルドの BP を `bp estimate` で再算出する
3. 全ビルドが `bp_max` 以下になるまで繰り返す

## 基準表を直したくなったら

このビルドの見積もりの中では直さない。振り返り（retrospective）に実測と申告を残し、
`/hikyaku:bp-guide` で `bp history` を素材に調整する。基準表はワークスペース全体に効くので、
1ビルドの都合で動かすと他のビルドの見積もりと比較できなくなる。
