# G1: user-stories の承認

user-stories.md をユーザーに提示し、承認を得る（G1）。要件の合意は後段の承認では代替できない
（設計も plan も「その要件で正しいか」を前提に置くため）。

- [ ] user-stories.md を提示し、承認を求める
  - レビューで反映した点があれば、何を直したかを添える
  - 値 `profile` を1行出し、このプロファイルのままでよいかを併せて確かめる（承認とレビューの量を
    決める委任の前提なので）。変えるならユーザーが決め、`cycles.md` とサイクル設定を直してから提示し直す
  - 値 `deferredConsent`（事後同意: 上限を超えるリスクの受け入れを止まらずに積み、マージの前にまとめて同意する）を
    1行出し、併せて確かめる。変えるならユーザーが決め、サイクル設定の `[consent] deferred` を直してコミットしてから、
    ユーザーの答えを `rejected` で報告し、提示し直す（承認の記録には、提示した値を `step report` が設定から読んで残す。
    最後の差し戻しの報告より後にコミットした値は、選んでいないものとして記録される）
  - 未決事項として記録した質問（いつ: `gate:G1`）があれば並べ、答えを `ledger decide plan <ID> {cycle} --by user --input` で記録する
