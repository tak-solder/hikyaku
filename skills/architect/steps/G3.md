# G3: 設計案の選択

トレードオフの選択は本来ユーザーにしか下せない判断なので、ユーザーの選択を得る。

- [ ] `options` でまとめた trade-off表と推奨案をユーザーに提示し、選択を得る（G3）
- [ ] 「お任せ」と回答された場合も、推奨案を改めて提示して明示的な確認を得る（空回答として進めない）
- [ ] 承認の `--input` には、選んだ案が分かるように書く
- [ ] 案の作り直しを求められたら、案を見直してから提示し直す

## 同意として返ったとき

directive の承認が同意（`承認: 同意（…）`）なら、AI に任せてよい上限を超える判断を含む回である。
提示の冒頭に、その理由（`approvalReason`。上限を超える害・重い領域・申告の欠け・基準を読めないなど）と、
どの案が上限を超えるかを書く。notices に基準の宣言を読めなかったことが出ていれば、それも添える。
ユーザーの選択を得るまで進めない。express で `designChoiceGate` が false だった回でも同じ。
