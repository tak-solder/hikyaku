# delegation: 委任を続けるかの確認（差し戻しのあと）

差し戻しからの再設計の回の先頭で返る。差し戻し（`return.md` の作成）は委任の前提（プロファイルで
決めた承認とレビューの量、conductor に任せたこと）が崩れた出来事なので、委任を続けるかをユーザーに
尋ねる（ask: delegation）。プロファイルを切り替えるかはユーザーが決める。あなたは切り替えない。

- [ ] 次をユーザーに提示する
  - 起きた出来事: `return.md` の要約（差し戻し元のビルド、何が崩れたか）
  - 現在のプロファイル（`hikyaku config {cycle}` の `profile`）と、conductor で進めているか
  - この回では、プロファイルに関わらず G3・G4 をユーザーが行うこと
  - 選択肢: このまま委任を続ける / ユーザーがプロファイルや委任の範囲を変える（変えるのはユーザー。
    頼まれればサイクル設定を書き換えてよい）/ conductor を止めて対話で進める
- [ ] 答えを `approved` の `--input` に書いて報告する。委任をやめる・プロファイルを変えると答えたときも
  `approved` で記録する（答えは `--input` に残る）。`rejected` は、提示を直して出し直すよう求められたときだけ
