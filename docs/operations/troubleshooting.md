# トラブルシューティング

## まず実行するもの

```bash
hikyaku doctor
hikyaku validate
```

（`hikyaku` はシェル関数です。未定義なら [実行方法](../reference/cli.md#実行方法) を先に済ませてください）

`doctor` は実行環境（Node のバージョン、設定ファイル、HIKYAKU_ROOT、origin への到達性）を、`validate` はファイルの整合性（ドキュメントガイドのパス、サイクル依存、tasklist の依存グラフ、issue.md の存在）を見ます。どちらも問題があれば終了コード 2 で終わります。

終了コードは `0` 成功 / `1` エラー / `2` 検証失敗です。`1` と `2` を分けているのは「実行できなかった」と「実行したが問題が見つかった」を区別するためです。

## 設定まわり

### リポジトリルートに .hikyaku.config がありません

初期化されていません。`/hikyaku:init` を実行してください。`hikyaku_root` はこのファイルでのみ宣言できます。

### {HIKYAKU_ROOT}/.hikyaku.config は読み込まれません

設定を置ける場所はリポジトリルートとサイクルディレクトリの2箇所だけです。中間層は v2.0 の初期実装が生成していたもので、現在は読み込みません。内容をリポジトリルートの `.hikyaku.config` へ移してから削除してください。

黙って無視せずエラーにしているのは、「設定したつもりの値が効かない」状態が最も気づきにくい壊れ方だからです。

### issue_backend は v2.0.0 で廃止されました

`[external] target` へ移行してください。完了判定が GitHub のライブ照会から `tasklist.md` の `PR` 列に変わるため、挙動が変わります。だから黙って読み替えることはしません。詳細は [v1 → v2 移行ガイド](../migration/v1-to-v2.md)。

### profile はサイクル設定では指定できません

`profile` はサイクルの属性で、`cycles.md` が唯一の正です。変えたい場合は `cycles.md` の該当行を編集してください。

### サイクル設定では上書きできないキーがあります

`hikyaku_root` / `base_branch` / `[branch]` / `[pr]` / `[session]` / `[external]` はリポジトリ全体の性質なので、ルートの `.hikyaku.config` に書きます。とくにブランチ名は全サイクル横断で解析するため、サイクルごとに規則が変わると着手状態を導出できなくなります。

### [branch].separator に空文字は指定できません

区切りが無いとブランチ名からサイクルとフェーズを切り出せません。`-` や `_` は使えます。

## ドキュメントガイド

### document-guide.md が見つかりません

存在しなければ Hikyaku は動作しません。`/hikyaku:init` で生成してください。

### document-guide.md の管理列が不正です

使える値は `hikyaku` / `repo` / `未作成` / `対象外` の4つだけです。タイプミスを黙って `対象外` に落とすと、登録済みのドキュメントが索引からも昇格対象からも静かに消えるため、エラーにしています。

### 未知の論理名です

論理名は増やせません。使えるものは [ドキュメントガイド](../configuration/documents.md#論理名) の表にあります。

### パスが存在しません

ポインタが指す先が消えています。ファイルを移動したなら `document-guide.md` のパス列を更新し、`hikyaku docs link` で AGENTS.md の索引も再生成してください。この検出ができることが、コピーではなくポインタを持つ利点です。

### 必要なドキュメントの行がありません

必須の論理名（overview / decisions / constraints / learnings / conventions）は、`未作成` や `対象外` であっても行が必要です。「意図的に持たない」と「まだ決めていない」を区別するためです。

## サイクルとビルド

### 対象サイクルを決められません

進行中のサイクルが複数あり、ブランチからも `.hikyaku.local` からも決まらない状態です。候補が表示されるので、引数で指定し直してください。

```
/hikyaku:builder 002-billing
```

`hikyaku cycle use 002-billing` で記録しておくと、次回から尋ねられません。

### slug が複数のサイクルに一致します

`closed` になった slug は再利用できるため、同名のサイクルが複数存在しえます。`active` が1つに絞れない場合はエラーになるので、ID かディレクトリ名で指定してください。

### cycles.md の status が不正です

使える値は `active` / `closed` / `abandoned` です。黙って `active` に落とすと次の書き込みでその値が永続化され、`closed` のはずのサイクルが復活するため、エラーにしています。

### tasklist.md に無いビルドです

ビルド番号のタイプミスか、まだ分割されていません。登録済みのビルドが一覧で表示されます。ビルドが無い場合は ARCHITECT フェーズで分割してください。

### 依存グラフに循環があります / 依存が存在しません

`tasklist add` / `tasklist update` は書き込む前に検証し、問題があれば書き込まずに終了コード 2 で終わります。`--deps` を修正して実行し直してください。

### 完了済みビルドは更新できません

`PR` 列が非空のビルドはスコープも依存も変更できません。依存グラフの整合性が崩れるためです。追加の作業が必要なら、新しいビルドを足してください。

## ブランチ

### branch verify が不一致（終了コード 2）を返す

各フェーズの冒頭では一致しないのが普通です（まだそのブランチに居ないため）。扱いは現在のブランチによって変わります。

| 状況 | 対応 |
|---|---|
| デフォルトブランチ上（`onBaseBranch: true`） | まだブランチを切っていないだけ。期待する名前で作成する |
| 別の作業ブランチ上（`false` / `null`） | ユーザーに尋ねる |

スクリプトが2つ目を自動で決めないのは、実行環境がブランチ名を決めている場合（クラウド版の Claude Code など）と、別の作業のブランチに紛れ込んでいる場合を外から区別できないためです。前者を黙って許すと後者も素通りします。

規則から外れたブランチで作業した場合に失うのは `next` の「着手中」表示だけです。完了判定と中断検出には影響しません。

### デフォルトブランチを特定できない（`onBaseBranch: null`）

`base_branch` が未設定で、`origin/HEAD` からも導出できない状態です。`.hikyaku.config` に `base_branch = "main"` を設定してください。`main` と推測することはしません。

## 進行状況

### next が何も返さない

全ビルドが完了しているか、すべてのビルドが依存待ちです。`cycle status` で確認してください。依存待ちであれば、先行ビルドの PR がマージされていない可能性があります。完了判定はデフォルトブランチの `tasklist.md` の `PR` 列で行うため、ローカルでマージしただけでは満たされません。

### 中断からの再開なのに最初からやり直そうとする

デフォルトブランチに居るまま `cycle status` を実行すると、別セッションが push した成果物が見えません。フェーズのブランチに切り替えてから実行してください。

成果物がコミット & push されていない場合も同様に見えません。成果物を1つ作るごとにコミットするのはこのためです。

### completed のまま止まっている

実装は main に入っているのに、永続ドキュメントへの昇格が終わっていない状態です。この期間に他サイクルの architect が走ると古い `overview` を現実として読みます。`/hikyaku:close-cycle` を実行してください。

## 外部連携

### gh CLI が無い（`reason: "gh-not-found"`）

投影内容自体は返るので、スキルが GitHub MCP ツールで適用し、`hikyaku cycle link` / `hikyaku tasklist link` で参照を記録します。エラーではありません。

### 投影に失敗した

警告が出ますが、ワークフローは止まりません（終了コード 0）。ファイル側が常にマスターなので、後から `hikyaku external sync` をやり直せば収束します。

## 環境

### Node.js のバージョンが足りない

v22.18.0 以上が必要です。v22.6.0〜v22.17.x では `--experimental-strip-types` を付ければ動きますが、Node 本体の更新を推奨します。

### .hikyaku.local が git 管理下に入っている

コミットすると他メンバーの栞を掴むことになります。

```bash
git rm --cached {HIKYAKU_ROOT}/.hikyaku.local
```

`{HIKYAKU_ROOT}/.gitignore` に1行あることも確認してください。

### origin に到達できない

着手中ブランチの検出ができなくなりますが、着手可能・待機の判定には影響しません（判定は `PR` 列だけで行うため）。
