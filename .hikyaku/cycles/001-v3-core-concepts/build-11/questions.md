## Q1: G8（plan と test-spec の承認）と、AI の解釈 1〜3

- 問い: plan.md と test-spec.md を承認するか。AI が解釈で決めた点（1. 理由の欠けた基準を rule に限る、2. `args.reworkFrom` の欄を足さない、3. 「このサイクルの ADR」をサイクルの文書にファイル名が現れる ADR とし、現れないものは同意に倒す）を、このまま進めてよいか
- 回答（委任された判断・監督）: 承認。解釈 1〜3 はこのまま進める
- 根拠（監督）:
  - issue.md の受け入れ基準はすべて test-spec.md のシナリオに対応している
  - 解釈1は、消す候補を減らす側で、働いている基準を誤って消す害（原則10）を避ける安全側。ただし US-9.2 の範囲を狭めるので、handoff の「残したこと」に「確度: 要確認」として残す（最後の PR でユーザーに示す）
  - 解釈2は、G10 へ戻る挙動を変えない実装の選択
  - 解釈3は、判断できないものを同意に倒す安全側
  - ADR approval-kind の再評価条件との食い違いは、ADR を書き換えずに handoff の「永続化すること」へ回す（原則6）
  - コンテキストの目安を超えての継続は、予測ピークが帯の中なので受け入れる
