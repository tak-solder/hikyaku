# Build 04: 質問

## Q1: G8（plan.md と test-spec.md の承認）

- 誰が決めたか: 監督（委任された判断）
- 回答: 承認（実装に進む）。条件を2つ付けた
  - 条件1: 害が高の異議で `decided` のとき、`--accepts` は求めないが、ユーザーが改めた選択をユーザーの言葉で残す欄（`--input`。`ledger decide --by user` と同じ扱い）を必須にし、欠ければ拒否する。テストに1シナリオ足す
  - 条件2: G8 より前に作業ツリーで書き始めていた未コミットの変更は、承認後の実装として扱う。plan.md に沿っているかを確かめ直してから続ける
- 根拠: 承認の記録を書くのは AI なので、`consented` の代わりに `decided` と書けば高の異議が止まらずに通る経路になりうる。ユーザーの言葉を必須にすれば、その経路を狭められる。受け入れ基準はすべて test-spec のシナリオに対応している。サイクルに属さない patch に異議の指示を載せないのは、スコープ外 Q12 のとおり。delegation を2回尋ねるのは、ユーザーに上げる側の振る舞い
- 受け入れた逸脱: Stop フック・step where・conductor parse が、作業単位の decisions.jsonl を1つ読む。design-delta.md 2節（その経路では読まない）からの逸脱だが、delegation を出すのに要り、読めないときはゲートが出る側に倒れる。handoff の「残したこと」に「確度: 要確認」として残す（監督が最後の PR でユーザーに示す）
