# Build 10: 知見の置き場の「なくす」と、rule を移すきっかけ・領域の開発頻度 質問

## Q1: G8（plan.md と test-spec.md の承認）

確認してほしい判断:
- patch の handoff は「レビューの記録」の集計に含めない（範囲外として handoff の「残したこと」に記録する）
- 休眠した領域について plan.md・codebase-survey.md に書くのは、基準の所在だけ（本文は写さない）

**回答**: 承認（実装に進む）。監督の委任された判断。
根拠: issue.md の受け入れ基準（US-4.1〜4.4・5.1〜5.5・9.1）はすべて test-spec.md のシナリオに対応し、plan.md の実装ステップは issue.md の「やること」に収まり「やらないこと」（基準を消す PR と指標の比較、置き場の判断そのもの）に踏み込んでいない。patch の handoff を集計に含めない判断は、移す候補が少なめに出るだけで成果物に害が残らず、handoff の「残したこと」に記録されるので受け入れる。休眠した領域について基準の所在だけを書く判断は、AGENTS.md の原則7（コピーではなくポインタ）どおり。
